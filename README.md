# Spanish Levels Map

**Your map of Spanish, A1–C2, explained in English.**

A static web app for learning Spanish from A1 to C2 with every explanation in English. For each level it lists what you need to know (the syllabus), explains each topic with examples, and lets you practice: four-question quizzes on a trail, exercise sets, flashcards with spaced repetition, a mistake log that brings errors back, a placement test, final tests per level and a Tense & Mood Lab. You tick off what you know and see your way to the top.

No accounts, no tracking, no server: progress is stored only in your browser (export / import as a JSON file).

The engine is a port of `english-levels-map` (the owner's Polish app for learning English). Everything that is about Spanish lives in `js/lang.js`, `js/config.js` and `content/`, so the engine can be copied for another language from the tag `engine-v1`.

## Run it

Nothing to install and no build step to *run* the app:

- **From disk:** double-click `index.html` (works from `file://`).
- **Local server** (recommended while editing): `python -m http.server 8765`, then open `http://localhost:8765/`.
- **GitHub Pages:** serve `main` from the repository root; the app works under a path such as `/spanish-levels-map/`.

Node (18+) is only needed to regenerate `data/` from `content/` and to run the checks.

## Commands

```
npm run build          # validate, then generate data/*.js and the search index
npm run build -- --bump   # also raise the version stamp (?v=) in index.html, js/config.js, package.json
npm run validate       # every validator (content, exercises, build checks)
npm test               # unit tests of the pure logic (no DOM)
npm run check:lang     # fails on Polish text, or on Spanish facts outside js/lang.js, js/config.js and content/
npm run contrast       # WCAG contrast of every token pair, both themes
npm run e2e            # browser tests (skipped when playwright-core or a Chromium browser is missing)
npm run assets         # copy fonts, Lucide icons and GSAP from node_modules into assets/ (after npm install)
```

`npm run e2e` needs `playwright-core` (for example `npm i --no-save playwright-core`, or `NODE_PATH` pointing at a copy) and Chrome, Edge or a Playwright Chromium (`CHROME_PATH` may name it). Helpers: `node tools/strip-keys.js <files>` prints items without the answer key (for the solver review of spec 10), `python docs/plan/scripts/validate_plan.py content` is the reference validator.

## Architecture

- Plain `<script defer src>` files, one global `window.LM`, no modules, no `fetch()`, no framework, no CDN. Big data files load on demand with `LM.loadModule()` (a `<script>` tag, so `file://` works).
- `content/` holds the **sources** (JSON and Markdown); `tools/build.js` turns them into `data/*.js` (committed, never edited by hand).
- DOM is built with `LM.utils.el`; user text goes in through `textContent` / `value`, never `innerHTML`.
- Language layer: `LM.APP` (`js/config.js`: names, storage prefix, voices, characters, report links) and `LM.lang` (`js/lang.js`: answer normalisation, accents, near-miss hints, folding for search). Every other file reads language facts from them.
- Design system: [`DESIGN.md`](DESIGN.md) (tokens, components, light and dark themes, accessibility).
- Plan and specs: [`docs/plan/00-READ-ME.md`](docs/plan/00-READ-ME.md).

```
index.html            app shell
css/                  style.css (tokens at the top), print.css
js/                   one file per feature; *-logic.js files are pure and unit-tested
assets/               fonts, icons, land symbols, GSAP (copied by npm run assets)
content/              SOURCES (see below)
data/                 GENERATED by npm run build
tools/                build/ (one module per data kind), validators, tests, e2e, contrast, check-lang, strip-keys
tools/fixtures/       test data; tools/fixtures/lang/ holds the language-dependent fixtures (spec 09)
docs/plan/            specs, syllabus, gold-standard examples, prompts
```

## Storage

Every key starts with `slm.` (`LM.APP.storagePrefix`); every access is wrapped in `try/catch`. All the owner's apps share one origin on GitHub Pages, so other prefixes (`elm_*`, `elm.`) are never read or written. The registry in `js/profile-data.js` (`LM.storage.REGISTRY`) lists every key; export, import, reset and profile deletion walk it, and a unit test checks that each key is covered.

| Key | Scope | Content |
|---|---|---|
| `slm.theme` | device | `auto` / `light` / `dark` |
| `slm.sidebar` | device | `{ version, pinned }` |
| `slm.ui` | device | the selected level (reset clears it) |
| `slm.search-recent` | device | recent searches |
| `slm.profiles` | app | profiles, active profile, "I know this" progress per topic id |
| `slm.journal`, `slm.activity`, `slm.placement`, `slm.celebrated`, `slm.exercises`, `slm.attempts`, `slm.autojournal`, `slm.prefs`, `slm.notes`, `slm.exams`, `slm.speaking`, `slm.finals`, `slm.phrases` | all profiles | `{ version, profiles: { <id>: … } }`: mistake log, study days, placement result, milestones, set scores, answer log, automatic log entries, learning settings, notes, exam dates and pins, speaking attempts, final tests, favorite phrases |
| `slm.cards.<profile id>`, `slm.trail.<profile id>` | one profile | flashcard state and decks; trail stops |

The backup file is `spanish-levels-map-YYYY-MM-DD.json`; a file from another app is refused with a message. Schemas start at version 1 (no migrations). Without storage (private mode) a banner warns and the app works until the tab closes.

## Content and data formats

The full model is in [`docs/plan/spec/07-content-model.md`](docs/plan/spec/07-content-model.md); gold-standard samples in `docs/plan/examples/`. Content is original: nothing is copied from textbooks, exam papers or other sites.

| Source | Format | Generated |
|---|---|---|
| `syllabus.json` | levels → units → topics (`id`, `title`, `category`, `examples`); **ids are frozen** | `data/syllabus.js`, `data/trail.js` |
| `levels.json` | `{ "levels": { "A1": "available" \| "soon", … } }` | level status everywhere (spec 06 E1) |
| `home.md` | Markdown with front matter; the "Levels at a glance" table links levels and its Status column follows `levels.json` | `data/pages.js` |
| `pages/<level>/<category>-<slug>.md` | front matter (`id`, `level`, `category`, `title`, `summary`) and fixed `##` sections per category | `data/pages.js` |
| `summaries/<level>.md`, `cheatsheets/<level>.md` | fixed sections; the cheat sheet fits one A4 / Letter page | `data/pages.js` |
| `quizzes/<level>/<topic id>.json` | 4 multiple-choice items (one may be a gap-fill), `passScore` 3 | `data/quizzes-<level>.js` |
| `exercises/<set id>.json`, `topics.json`, `mixes.json` | 10 items of at least four types (multiple-choice, reorder, find-error, short-answer, gap-fill, match, transformation, translate, dictation, paradigm) | `data/sets/*.js`, `data/sets-index.js` |
| `tests/placement.json`, `tests/final-<level>.json` | placement: 10 questions per level; final test: 30 items, draw 20, pass 80 % | `data/placement.js`, `data/final-<level>.js` |
| `decks/index.json`, `decks/<deck id>.json` | `typed` and `cloze` cards | `data/decks-index.js`, `data/decks/*.js` |
| `lab/cards.json`, `lab/contrasts.json`, `lab/trees.json` | grid axes and cards (formation rows, uses, timeline scenes, traps, contrasts); contrast cards (two sides of rules, 4-item quiz); decision trees (nodes, options, results) | `data/lab.js` |
| `writing/phrases.json`, `exams/registry.json` | phrase bank; exam registry | `data/…` |

All validators run in `npm run build`; `npm run validate` adds the content rules of spec 06 E11 (answers, accents, gender and region notes, one correct option, charset).

### Add a topic page

1. Find the topic in `content/syllabus.json` (the id is fixed, e.g. `a1-verbs-ser`).
2. Write `content/pages/a1/verbs-ser.md` with the front matter and the sections of its category (spec 07 §1).
3. Write the trail quiz `content/quizzes/a1/a1-verbs-ser.json` (spec 07 §4).
4. `npm run build`, open `#/a1/verbs-ser`. The trail stop picks the quiz up by itself.

### Add an exercise set

1. Write `content/exercises/<topic id>-<n>.json` (10 items, ids `<set id>-NN`).
2. Add the set id under the topic in `content/exercises/topics.json`; for a unit review, an entry in `mixes.json`.
3. `npm run build`; the set appears on the topic page, in Practice and on the trail.

### Add a deck

1. Write `content/decks/<deck id>.json` (cards `<deck id>-NNN`, `level`, `tags`).
2. Add the deck to `content/decks/index.json` (`id`, `title`, `description`, `level`, `file`, `count`, `enabled`).
3. `npm run build`.

### Make a level available

1. Every topic of the level has a page and a quiz; `summaries/<level>.md`, `cheatsheets/<level>.md` and `tests/final-<level>.json` exist (spec 10 §7).
2. Set the level to `"available"` in `content/levels.json`.
3. `npm run build` (the build checks completeness), then `npm run validate`, `npm test`, `npm run e2e`.

Content follows the pipeline of spec 10: write → validate → a solver review on items without the key (`tools/strip-keys.js`) → a native proofreader review → fix → build.

## Reporting mistakes

Every topic page, quiz and set result and built-in flashcard has a "Report a mistake" link (an issue form with the topic id in the title; e-mail when `LM.APP.reportMail` is set).
